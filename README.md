# Склад закупок

Сайт для складского учёта закупок центра (призы, сувенирка, расходники):

- приход по счёту, УПД или накладной (PDF, фото, скан) с распознаванием позиций;
- распределение доставки и нанесения по себестоимости;
- учётные названия и группы товаров, запоминание названий из документов;
- ожидаемые поставки и сопоставление УПД со счётом;
- списание на проекты, остатки, инвентаризация, журнал, выгрузка в CSV;
- вход по логину и паролю, три роли: администратор, сотрудник, только просмотр.

Данные хранятся в одном файле `data/sklad.db`.

## Что понадобится

1. **Сервер (VPS)** с Linux: 1 процессор, 1–2 ГБ памяти, 10 ГБ диска. Подойдёт Ubuntu 22.04 или 24.04.
2. **Адрес** для сайта, например `sklad.kazan-math.info`: у домена создайте запись типа A на IP-адрес сервера.
3. **Ключ API для распознавания документов** (по желанию): Яндекса или Anthropic, см. ниже.

### Распознавание: Яндекс или Claude

Провайдер выбирается строкой `AI_PROVIDER` в `.env`.

**`AI_PROVIDER=yandex`** (для сервера в России). Текстовые PDF читаются прямо в браузере, сканы и фото по одной странице уходят в Yandex Vision OCR, затем полученный текст разбирает YandexGPT (или Alice AI) в таблицу позиций. Что нужно:

1. В [AI Studio](https://aistudio.yandex.ru) или консоли Yandex Cloud создайте платёжный аккаунт и каталог, скопируйте идентификатор каталога (folder ID).
2. Создайте сервисный аккаунт с ролями `ai.languageModels.user` и `ai.vision.user` и API-ключ для него.
3. Впишите в `.env` на сервере `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. В чат и в почту ключ не отправляйте.

При `AI_LOG=1` полные ответы Яндекса (что распознал OCR и что вернула модель) складываются в `data/ai-log`. По ним видно, на каком шаге ошибка: OCR не прочитал строку или модель неправильно её разобрала. Модели меняются строками `YANDEX_MODEL` и `YANDEX_OCR_MODEL`.

**`AI_PROVIDER=anthropic`** (Claude). Читает сканы точнее, но API Anthropic не принимает запросы из России: сервер должен стоять за рубежом, оплата зарубежной картой. Нужен `ANTHROPIC_API_KEY`.

Если ключа нет, сервис всё равно работает: распознавание выключено, приход вносится вручную или вставкой текста документа. Остальное (остатки, списания, инвентаризация, журнал, роли) от ИИ не зависит.

## Установка на сервер с ботами (Beget, nginx уже стоит)

Код лежит в `/opt/sklad`, сайт `https://sklad.kazan-math.info`, приложение слушает только `127.0.0.1:8300`, наружу его отдаёт nginx. Все команды выполняются на сервере под root.

**0. Перед началом.** Тариф VPS увеличен (рекомендуется 2 CPU и 4 ГБ), DNS-запись типа A `sklad.kazan-math.info` указывает на IP сервера. Проверить память после увеличения: `free -h`.

**1. Ключ доступа к репозиторию.** Репозиторий приватный, серверу нужен ключ только для чтения:

```bash
ssh-keygen -t ed25519 -N "" -f /root/.ssh/sklad_deploy -C sklad-deploy && cat /root/.ssh/sklad_deploy.pub
```

Выведенную строку добавить на GitHub: репозиторий → Settings → Deploy keys → Add deploy key (галочку «Allow write access» НЕ ставить).

```bash
git clone -c core.sshCommand="ssh -i /root/.ssh/sklad_deploy" git@github.com:mrusakova/sklad-service.git /opt/sklad && cd /opt/sklad && git config core.sshCommand "ssh -i /root/.ssh/sklad_deploy"
```

**2. Настройки.**

```bash
cd /opt/sklad && cp .env.example .env && chmod 600 .env && nano .env
```

Заполнить `ADMIN_LOGIN`, `ADMIN_PASSWORD` (можно сгенерировать: `openssl rand -base64 18`), `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`. `DOMAIN` здесь не нужен.

**3. Запуск и проверка.**

```bash
cd /opt/sklad && mkdir -p data && chown 1000:1000 data && chmod 700 data && docker compose up -d --build
```

```bash
docker compose -f /opt/sklad/docker-compose.yml logs --tail 20 app && curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8300/login.html
```

В логе должна быть строка «Склад закупок: … (распознавание: yandex …)», curl должен вывести `200`.

**4. nginx и HTTPS.**

```bash
cp /opt/sklad/deploy/nginx/sklad.kazan-math.info /etc/nginx/sites-available/ && ln -s /etc/nginx/sites-available/sklad.kazan-math.info /etc/nginx/sites-enabled/ && nginx -t && systemctl reload nginx
```

```bash
certbot --nginx -d sklad.kazan-math.info
```

**5. Бэкап** (каждую ночь в 3:45, хранятся 30 дней в `/var/backups/sklad`):

```bash
cp /opt/sklad/deploy/cron /etc/cron.d/sklad && sh /opt/sklad/deploy/backup.sh && ls -la /var/backups/sklad/
```

**Обновление** после изменений в репозитории:

```bash
cd /opt/sklad && git pull && docker compose up -d --build
```

## Установка на отдельный сервер с Docker и Caddy

Все команды выполняются на сервере по SSH.

1. Установите Docker:

   ```
   curl -fsSL https://get.docker.com | sh
   ```

2. Загрузите папку `sklad-service` на сервер, например в `/opt/sklad` (через WinSCP, FileZilla или `scp`) и перейдите в неё:

   ```
   cd /opt/sklad
   ```

3. Создайте файл настроек и откройте его для правки:

   ```
   cp .env.example .env
   nano .env
   ```

   Заполните `DOMAIN`, `ADMIN_LOGIN`, `ADMIN_PASSWORD` (не короче 8 символов) и ключи распознавания (`YANDEX_API_KEY` и `YANDEX_FOLDER_ID` либо `ANTHROPIC_API_KEY`). Сохраните: Ctrl+O, Enter, Ctrl+X.

4. Запустите:

   ```
   mkdir -p data && chown 1000:1000 data && docker compose --profile caddy up -d --build
   ```

   Первый запуск занимает несколько минут. Адрес получит https-сертификат автоматически (порты 80 и 443 на сервере должны быть открыты).

5. Откройте `https://ваш-адрес`, войдите под администратором и создайте остальных пользователей на вкладке «Пользователи».

## Установка без Docker

Нужен Node.js версии 20 или новее.

```
npm ci --omit=dev
cp .env.example .env     # заполните ADMIN_LOGIN, ADMIN_PASSWORD, ANTHROPIC_API_KEY
npm start
```

Сайт откроется на `http://localhost:3000` (порт меняется в `.env`). Для работы в интернете поставьте перед ним nginx или Caddy с https. Для nginx в настройках нужны `client_max_body_size 60m;` и для пути `/api/events` отключённая буферизация (`proxy_buffering off;`). Чтобы сервис запускался сам, оформите его как службу systemd.

Такой запуск удобен и для пробы на своём компьютере. Без https на публичном адресе его использовать нельзя.

## Роли

| Роль | Что может |
|---|---|
| Администратор | всё, а также пользователи и резервная копия |
| Сотрудник | приход, списание, инвентаризация, справочники, журнал |
| Только просмотр | остатки и журнал |

## Обслуживание

**Резервная копия.** Войдите администратором, откройте «Пользователи» и нажмите «Скачать копию базы». Делайте это раз в неделю и перед обновлением, храните файл отдельно от сервера. Файл можно также просто скопировать из папки `data` (лучше при остановленном сервисе).

**Восстановление.** Остановите сервис, положите копию в `data/sklad.db` и запустите снова.

**Забыли пароль администратора** (Docker):

```
docker compose exec app node cli.js set-password логин новый-пароль
```

Без Docker: `npm run user -- set-password логин новый-пароль`. Новый пользователь из командной строки: `cli.js add-user логин пароль admin|staff|viewer "Имя"`.

**Обновление.** Замените файлы программы новой версией (папку `data` и файл `.env` не трогайте) и выполните `docker compose up -d --build`.

**Логи.** `docker compose logs -f app`.

## Безопасность

- Работайте только по https. Пароль администратора делайте длинным.
- Ключ API хранится только на сервере, в файле `.env`. Никому его не отправляйте, не выкладывайте и не добавляйте в репозиторий.
- На распознавание тратятся деньги с вашего ключа API. Следите за расходом в консоли Яндекса или Anthropic и при желании установите там лимит.
- В `data/ai-log` лежат тексты распознанных документов. Когда проба закончится, можно выключить журнал (`AI_LOG=0`) и удалить папку.
- Не открывайте порт 3000 наружу, пусть сайт доступен только через Caddy или nginx.

## Как это устроено

- `server.js`: сервер (Express, SQLite), вход по логину, роли, обмен с базой, обращение к Claude API или к Яндексу (`/api/ai`, `/api/ocr`).
- `public/index.html`: сам сайт. Страница `login.html`: вход.
- `public/vendor`: библиотека чтения PDF (pdf.js), чтобы не зависеть от внешних сайтов.
- `cli.js`: управление пользователями из командной строки.
- Модели распознавания можно поменять переменными `AI_MODEL` и `AI_MODEL_QUICK` (Claude), `YANDEX_MODEL` и `YANDEX_OCR_MODEL` (Яндекс) в `.env`.
