### Сервер

- Данные: одна таблица `docs(col, id, data JSON, updated)` для коллекций `items`, `projects`, `receipts`, `moves`, `inventories`; таблицы `users` и `sessions`.
- API: `GET /api/c/:col`; `PUT`, `PATCH` (слияние верхнего уровня), `DELETE /api/c/:col/:id`; `GET /api/events` (SSE, сообщение `{"c":"items"}` при изменении); `POST /api/ai` (прокси к Claude API); `/api/users` и `/api/backup` только для администратора; `/api/login`, `/api/logout`, `/api/me`.
- Защита: сессионная cookie (HttpOnly, SameSite=Lax, в базе хранится sha256 токена), пароли scrypt, не больше 10 неудачных входов за 10 минут с адреса, заголовок `X-Requested-With: sklad` обязателен для изменяющих запросов, CSP, роли `admin`, `staff`, `viewer` (viewer не пишет, сервер это проверяет).
- Переменные окружения: `PORT`, `DATA_DIR`, `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `ADMIN_NAME` (создание первого администратора), `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`, `AI_MODEL` (по умолчанию `claude-sonnet-5-5`), `AI_MODEL_QUICK` (по умолчанию `claude-haiku-5-5`), `SESSION_DAYS`.

## 4. Модель данных

- `items/{id}`: `name` (учётное название), `group`, `unit`, `aliases[]` (названия из документов поставщиков), `minQty`, `createdAt`.
- `projects/{id}`: `name`, `archived`. Посеяны: Лига Х, Лига профессионалов, Турнир Нордена, Турнир Широкова, Турнир Чеботарёва, Городская олимпиада 2–6 классов, Математические лагеря, Общие нужды центра (в версии Б база пустая: проекты заводятся на вкладке «Справочники»).
- `receipts/{id}`: `docType` (счёт, УПД, накладная, другое), `docNo`, `date`, `supplier`, `status` (`ordered` или `received`), `method` (`value`, `qty`, `equal`), `delivery`, `docSum`, `total`, `lines[]`, `receivedAt`, при закрытии счёта УПД ещё `invoiceNo`, `invoiceDate`, `invoiceType`, `invoiceSum`. Строка: `role` (`goods`, `addon`, `delivery`, `ignore`), `addonTo`, `itemId`, `accountName`, `group`, `qty`, `price`, `sum`, `share`, `addon`, `total`, `unitCost`.
- `moves/{id}`: `type` (`in` или `out`), `itemId`, `itemName`, `qty`, `unitCost`, `date`, для прихода `receiptId` и `docRef`, для списания `projectId`, `projectName`, `note`, `batch`; для инвентаризации `kind:"inventory"` и `inventoryId`.
- `inventories/{id}`: `date`, `note`, `counted`, `shortage`, `surplus`, `rows[]`.

Остаток считается не хранится: сумма `in` минус сумма `out` по `itemId`.

## 5. Правила учёта (не менять без согласования)

- **Роли строк документа.** `goods` попадает на склад. `addon` (нанесение, печать, брендирование, упаковка) прибавляется к себестоимости товара, указанного в `addonTo` (номер строки с 1). `delivery` образует пул доставки. `ignore` не учитывается.
- **Себестоимость.** Для товара: `база + нанесение + доля доставки`, делится на количество. Доставка распределяется по выбору: пропорционально стоимости (база плюс нанесение), количеству или поровну. Цены берутся с НАЛОГОМ, как в документе. Проверочный пример (счёт УТ-52): колонка 740 ₽ + печать 70 ₽ + доставка 17,55 ₽ = 827,55 ₽ за штуку; значок 19 ₽ + 0,41 ₽ = 19,41 ₽; итого 36 780 ₽.
- **Средняя себестоимость.** Скользящая средняя (согласовано 02.11.2026, до этого была средневзвешенная по всем приходам, включая списанные): стоимость остатка = сумма приходов минус сумма списаний по их зафиксированной цене, средняя = стоимость / количество. При нулевом остатке средняя = цена последнего прихода. Списание и недостача идут по средней на момент операции и фиксируются в записи, излишек оприходуется по средней, поэтому она не меняется.
- **Счёт или УПД.** Счёт не документ поступления: его можно сохранить как «ожидаемую поставку» (`ordered`, остатки не меняются) и принять позже с фактическим количеством. УПД или накладную можно привязать к ожидаемому счёту (подсказка по совпадению позиций и поставщика): счёт закрывается, на склад поступает по данным УПД. Если в счёте была доставка, а в УПД её нет, предлагается добавить её отдельной кнопкой.
- **Инвентаризация.** Заполняются только пересчитанные строки. Недостача: списание с проектом «Недостача по инвентаризации». Излишек: приход. Всё видно в журнале, отменяется поштучно.
- **Защита от ошибок.** Нельзя списать больше остатка, повторный документ с тем же номером, датой и поставщиком требует второго нажатия, удаление и отмена записей через кнопку с подтверждением.

## 6. Распознавание документов

Цепочка в браузере (функция `recognize()`):

1. Файл PDF: текст берётся из PDF библиотекой pdf.js (строки группируются по координате). Если текста почти нет (скан), страницы рисуются на canvas (длинная сторона 3200 пикселей).
2. Фото и скриншоты загружаются как изображения.
3. Для изображений: отдельный лёгкий запрос «на сколько градусов повернуть по часовой» на миниатюре (быстрая модель), поворот по результату или вручную из выпадающего списка; затем страница режется на 2 горизонтальные полосы с перекрытием 5% (если страниц хватает при лимите числа изображений), чтобы мелкий шрифт читался в полном разрешении.
4. Основной запрос: текст и (или) изображения плюс подробный промпт; ответ строго JSON: `docType`, `docNo`, `date`, `supplier`, `total`, `warnings[]`, `lines[]` с полями `rowNo`, `article`, `name`, `unit`, `qty`, `price`, `sum`, `role`, `addonTo`, `matchItemId`, `accountName`, `group`.
5. В промпт передаются справочник товаров (до 300) и существующие группы, чтобы Claude подбирал названия и группы из имеющихся.
6. Особые правила для УПД: сумма строки берётся из графы 9 (с налогом), цена = сумма / количество, итого из «Всего к оплате». Модель обязана сообщать в `warnings` о пропусках нумерации и нехватке листов.
7. Совпадение с уже известными товарами выполняется локально по псевдонимам (`aliases`) ещё до учёта ответа модели.

## 9. Грабли, на которые уже наступили

- **Нельзя `pkill -f "node server.js"`** в командах оболочки: шаблон совпадает с командной строкой самой оболочки и убивает её (код выхода 144). Запускайте через скрипт с pid-файлом или `pkill -x node`.
- **События `close` у `req`** в Node 16+ срабатывают сразу после чтения тела запроса. Для отмены ИИ-запроса и закрытия SSE используйте `res.on('close')`.
- **`change` и перерисовка.** Событие `change` поля ввода срабатывает при потере фокуса, то есть при нажатии на кнопку (между mousedown и mouseup). Если обработчик `change` перерисовывает вкладку, кнопка пропадает, и клик теряется. Перерисовывайте только при смене выпадающих списков, не полей ввода (так исправлено во вкладке «Списание»).
- **Тесты не идемпотентны**, перед каждым запуском e2e удаляйте `DATA_DIR`. В заглушке `mockai.js` формат ответа выбирается по тексту после «Текст документа:», иначе справочник в промпте даёт ложные совпадения.
- **В версии А** (артефакт) действовали ограничения: загрузка скриптов только с cdnjs, нет `confirm()` и `alert()`, скачивание только через capability `downloads`. В версии Б они не действуют, кроме CSP сервера (`script-src 'self' 'unsafe-inline'`), поэтому внешние скрипты надо класть в `public/vendor`.
- Google Fonts (PT Sans, PT Serif Caption) подключены с запасными шрифтами; в России может блокироваться, вёрстка при этом не ломается.
